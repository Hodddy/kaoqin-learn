7.6　Docker 容器化（大公司常要）

本课目标：理解 Docker 解决的"在我电脑好好的，到服务器就崩"的问题。

① 问题：环境不一致

你电脑装了 Python、各种库、版本正好；换台服务器可能版本不同、少装东西，程序就跑不起来。Docker 把"程序 + 它需要的整个环境"打包成一个集装箱，到哪台机器都一模一样。

🔑 Docker = 把程序连同环境装进"集装箱"，搬到哪都原样运行。

词做饼干里对应死/活
Dockerfile配方说明书（这模具怎么做）一张纸
镜像 Image照配方做出的饼干模具(模板)死的·能复制分发
容器 Container拿模具压出的那块饼干（真在用的）活的·正在跑
🔑 写配方(Dockerfile) → docker build 出模具(镜像) → docker run 出饼干(容器)。
一个模具能压很多块饼干 = 一个镜像能 run 出很多个容器。

类比你熟的：电脑上那个 .exe ≈ 镜像（打包好的成品）；双击它跑起来的窗口 ≈ 容器（运行实例）。Docker 更狠——连整个运行环境都打包进镜像，所以搬到哪台机器跑出来都一模一样。

③ 跟我们项目 & IT 的关系

给本项目写个 Dockerfile（装 Python、装依赖、拷代码、启动 uvicorn），就能交给 IT 一个标准镜像——他们不用关心你的环境细节，run 一下就起来。大公司很多只接收 Docker 镜像，这会让对接顺很多。

④ 小结

Docker=程序+环境打包镜像=模板/容器=实例Dockerfile 写打包步骤到哪都一样
🧠 记忆点：Docker 把"能跑的整套环境"装箱，消灭"在我这没问题"
