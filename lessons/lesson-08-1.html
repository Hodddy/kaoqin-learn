8.1　Git / GitHub 协作（你已经在用了）

本课目标：把这些天我们一直在做的 git 操作，串成概念。

① Git = 代码的"时光机 + 存档"

Git 记录你每一次改动，能回到任何一个历史版本、能多人合作不互相覆盖。GitHub 是把 Git 仓库存到云端的网站（我们的 Hodddy/Hengtai 就在上面）。

② 四个核心动作（你都见过）

命令意思
git add把改动"挑进待提交"
git commit存一个档（带说明）
git push把本地存档推到 GitHub 云端
git pull把云端最新拉到本地
🔑 改完 → add → commit（存档）→ push（上云）。我们这几天一直在循环这个。

③ 分支(branch)

分支=平行的开发线。我们把所有工作合到了 main 分支、删掉了 master。多人协作时常各开分支、做完合并(merge)，互不干扰。

④ 多人协作：先拉后推（重要）

这个项目不止你一个人改（已经有协作者在改）。多人共用一个仓库，规矩升一级：先 pull，再 push。

动手前 → git pull   # 先拿别人最新的，基于最新版改
改完   → git add / commit
推之前 → git pull   # 万一这期间别人推了，先合并
       → git push
  • push 被拒（报 non-fast-forward / rejected）= 云端已比你新 → 先 git pull 合并，再 push（最常见）。
  • 冲突 conflict：你和别人改了同一处 → git 在文件里标出两段，你手动选保留哪段、改好，再 commit。
  • 推之前先 git status 看清要提交啥，别 git add -A 一股脑全加（容易把不该提交/不该公开的东西也带上去）。
协作模式怎么做适合
简单版都在 main 上，但严格"先拉后推"2-3 人
正规版每人开自己分支 → 发 Pull Request(PR) → review 后合并 main多人 / 长期 / 要稳
🔑 一个人：改完 push 就行；多人：push 前先 pull，否则会冲突 / 覆盖别人。

⑤ 小结

Git=版本时光机add→commit→push分支=平行开发线多人：先拉后推
🧠 记忆点：commit 是存档，push 是上云；多人改 → push 前先 pull
