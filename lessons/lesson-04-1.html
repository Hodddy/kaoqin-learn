4.1　Web 框架是什么 · 为什么用 FastAPI

本课目标：理解"框架"帮你省了什么，为什么不从零造。

① Web 框架 = 处理 HTTP 的脚手架

还记得模块 1 的"请求/响应"吗？真要自己处理网络连接、解析请求、拼响应，非常繁琐。Web 框架把这些脏活包好了，你只管写"收到这个请求该回什么"。

🔑 框架 = 别人搭好的厨房骨架，你只管炒菜，不用自己砌灶台。

② 为什么选 FastAPI

  • 简单：几行就能写一个接口。
  • 快、现代，自带数据校验和自动文档。
  • Python 生态主流，资料多。（Flask 是另一个流行选择，概念相通。）

③ 在我们项目里（用"开餐厅"理解）

代码开餐厅里对应
app = FastAPI()盘下一家餐厅、摆好前台（餐厅有了，菜单还空着）。app 就代表"你这个 Web 应用本身"。
@app.get("/api/clients")
（写在函数上面）		往菜单加一道菜：把"取客户列表"这个服务挂到 app 上。每个接口（取客户/上传核对/下载）都是一道菜。
uvicorn web.server:app开门营业的店员：把这个 app 跑起来，盯着端口、接客、按菜单上菜。
🔑 app = 餐厅 + 菜单（定义"有哪些服务"，静止的）；uvicorn = 开门营业的店员（真正让它跑起来对外服务）。app 管"提供什么"，uvicorn 管"运行起来"。

④ 小结

框架=处理HTTP的脚手架只写"收到啥回啥"FastAPI 简单现代
🧠 记忆点：框架搭好骨架，你只写业务这道菜
