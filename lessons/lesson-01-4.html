1.4　HTTP 深入：请求 / 响应 / 方法 / 状态码

本课目标：把"一问一答"拆到零件级，看懂一次真实请求里到底有啥。

① 回顾：HTTP = 一问一答

浏览器（客户端）发一个请求，服务器回一个响应。这节我们把"请求"和"响应"各自拆开，看里面的零件。

🔑 请求 = 方法 + 地址 + 头 + 体；响应 = 状态码 + 头 + 体。

② 拆开一次真实请求/响应（我们项目的"开始核对"）

① 请求 Request（浏览器发出）
POST /api/reconcile        ← 方法 + 地址
Host: 127.0.0.1:8000       ← 去哪台机器
Content-Type: multipart    ← 我带的是"文件"
（body）公司.xlsx + 客户.xls ← 带的数据
方法=POST（我交东西）地址=核对窗口　头=附加说明　体=两个 Excel
② 响应 Response（服务器回来）
200 OK                     ← 状态码：成功
Content-Type: application/json
（body）{ "ok_total":36,
         "err_total":3, ... }  ← 结果数据
状态码=200（成了）　头=我回的是 JSON　体=核对结果

③ 方法：你想"干嘛"

方法意思项目里的例子
GET给我看 / 给我拿打开网页、/api/clients 取客户列表、下载结果
POST我交东西给你（新建/提交）/api/reconcile 上传两个文件来核对
PUT更新 / 设置成…（就是我们改 GitHub 权限时用的那个，把某人设成 admin）
DELETE删掉（移除一个协作者）

记口诀：GET 拿、POST 交、PUT 改、DELETE 删。

④ 状态码：这单"成没成"

范围含义常见
2xx成功200 成功；204 成功但没内容返回
3xx跳转（去别处）301/302 网址搬家了
4xx你（客户端）错了404 找不到；403 没权限；400 你发的内容有问题
5xx服务器自己错了500 服务器内部出错（厨房翻车）

记法：4 开头怪你，5 开头怪服务器。你上网见过的"404 页面不存在"就是这个。

⑤ 头(Headers) 和 体(Body) 是啥

· 头 Headers = "附加说明的小纸条"：我能接受什么格式、我带的内容是什么类型、我是谁（带身份令牌）等。
· 体 Body = "真正要传的货"：上传的文件、提交的数据、返回的结果。
（我们之前调 GitHub API 卡了半天，根因就是"头"里少写了 Content-Type: application/json，对方没认出体里的内容——你已经实战见过头的重要性了。）

⑥ 动手 & 小结

✍️ 动手 3 分钟（亲眼看真实请求）

  1. 浏览器打开任意网页 → 按 F12 打开开发者工具 → 选 Network（网络） 标签。
  2. 刷新页面，你会看到一条条请求；点开一条，能看到它的方法、地址、状态码、头、体——和本课讲的一模一样。
  3. （看不懂没关系，先建立"原来一次点击背后是这样一问一答"的画面感。）

✅ 小结

请求 = 方法+地址+头+体 响应 = 状态码+头+体 GET拿/POST交/PUT改/DELETE删 4xx怪你·5xx怪服务器
🧠 记忆点：一次点击 = 一封"请求信"寄出 → 收到一封"响应信"
