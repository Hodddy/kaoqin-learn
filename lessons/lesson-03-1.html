3.1　项目分层：core / clients / app / web 为什么这么分

本课目标：看懂项目的文件夹结构，知道每层负责啥。

① 为什么要"分层"

所有代码堆一个文件里，改一处牵一发动全身。分层 = 各司其职、互不打扰：业务逻辑只写一遍，桌面版、Web 版都来调用，改外壳不影响算账。

🔑 把"算账的"和"给人看的"分开，是好项目的第一原则。

② 我们项目的四层

文件夹负责
core/与客户无关的共享核心：解析、年月识别、模型、服务层
clients/每个客户一套：客户A的读取、核对规则、罚款、写出
app/桌面外壳（PySide6 界面）
web/网页外壳（FastAPI 后端 + 前端页面）

③ 关键：外壳变，核心不变

桌面版(app)和 Web 版(web)调用的是同一个 core/service.py: run_reconcile。
所以我们做 Web 版时，"算账逻辑一行没重写"——这就是分层的威力。

④ 小结

core=共享核心clients=各客户app=桌面壳web=网页壳
🧠 记忆点：核心(core)只写一遍，外壳(app/web)随便换
