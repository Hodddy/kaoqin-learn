0先记一个比喻：去餐厅吃饭

你只负责"点单 + 吃"，真正做菜的是厨房。浏览器也一样：只管提要求、显示结果，干活的是服务器。

1HTTP = 说话的规矩，核心就四个字"一问一答"

网页上你每点一下，基本就是这样"问一句、答一句"。

2一次"问"和"答"里各有什么

① 问（请求）像点单

  • 方法：GET=给我看/拿；POST=我交东西给你（上传 Excel）
  • 地址：去哪个窗口，如 /api/reconcile（核对窗口）
  • 带的东西：POST 时附上的数据（你的两个考勤表）

② 答（响应）像上菜

  • 状态码：200=成功；404=找不到；500=出错
  • 数据：一个网页 / 一段结果 / 一个可下载文件

3本项目的本地架构（全在你一台电脑里）

127.0.0.1 = "我自己这台电脑"；8000 = "8 千号窗口"。双击 bat = 在你电脑里开厨房、守在 8000 号窗口。

4后面有没有数据库？

目前没有，也不需要 ✓

数据库 = 一个长期保存数据的仓库，关机断电都还在、以后能翻出来查。本项目是"算完即走"：

不存历史、不存账号、不记谁何时核对过什么 —— 没有"要长期记住的东西"，自然不用仓库。

⏳ 将来这些情况才需要加数据库：

  • 想保存历史核对记录，以后能翻（界面左边灰色的"历史记录"就是给它占的位）
  • 想要多人登录，各看各的
  • 想在线管理多个客户 / 月份配置（现在写死在代码 config 里）
